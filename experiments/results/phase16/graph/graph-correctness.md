## Sample limits, threats to validity and missing data

- One export (size S, run:ba7402d1-959a-4277-8c6e-e92878a38afa) is checked; the result describes that bounded run, not the full corpus or later runs.
- The checks read the CSV sidecar generated from the same Spark tables by the same job; a defect common to both would not show. The Parquet tables are not read (no stdlib Parquet reader), so the support table and the integrity/violations table are unverified here.
- The audit checks internal consistency (every edge traces to authored works and resolved nodes). It does not check the facts against the original sources (DBLP, OpenAlex, Crossref, ORCID), so a wrong merge made upstream by entity resolution would pass these checks.
- The provenance audit samples 50 coauthor rows with a fixed seed; 50 of 50 resolved, so the Wilson 95% interval of the resolution rate is 92.9%-100.0%, not certainty.
- Window-specific correctness (that a work belongs to the year window of an edge) is not checked: the CSV sidecar carries no work years.
- Known small-graph tests are listed from source, not run by this package; their pass state comes from the recorded full check cited above, which ran on a different tree than the current HEAD.

## Gaps (not measured, with the reason)

- **support rows read from Parquet (edges/type=coauthored_with_support)**: no stdlib Parquet reader in an offline stdlib-only package; the support works stored on the CSV coauthor rows are used, and the Parquet row count is compared via the load manifest
- **integrity/violations and integrity/rejects Parquet contents**: Parquet not readable here; the Spark job's own counters (missingGraphEndpoints and related) are quoted as a cross-check
- **agreement of graph content with upstream source records**: needs the source data and an independent gold set, outside this offline package
- **window membership of support works by publication year**: work years are not in the CSV sidecar
