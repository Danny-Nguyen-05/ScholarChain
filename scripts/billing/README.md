# Initial billing-budget execution wrapper

This directory is an authoring artifact. It grants no live authorization. Use only after independent script review, the human's source-control/clean-checkout decision, G1 affirmation and personally written exact-plan/actor/window gate. The infra-engineer authors; a separately routed deploy-engineer executes approved source-controlled scripts. No AWS resources or IAM were changed while writing or testing these files.

Production CLI exposes exactly four modes: `p3-check`, `apply`, `readback`, `post-freeze-scan`. Run through `python3 -I scripts/billing/budget_execution.py`. Every mode requires `--gate`, `--gate-sha256` and `--operation`. Scan also requires `--public-manifest` and `--public-manifest-sha256`. There is no path/profile/region/plan override, test mode, automatic plan, login, import, destroy, policy repair or retry command. The plan is the reviewed 6,631-byte `ab9f141e83058209263cf561eef1d102496ec7f534b88ce421620d8e0045f855` artifact; all production paths and the uid501 owner are fixed in code. Do not invoke a production mode during authoring/review.

## Existing human gate represented as data

The JSON gate is a machine-readable representation of the already required human decision, not an agent-written approval or a new approval cycle. The human supplies the affirmation and personally writes/owns the approval. The coordinator may validate schema and hash without changing its meaning. A hash proves byte binding, not who authored it; independent review of human provenance remains required.

`load_gate` documents the exact accepted key set. Fields bind the operation, full plan/proposal hashes, source commit and all wrapper-file hashes, human record hash and own-words G1 affirmation, exact caller/account/profile/region, explicit offset-aware dated start/end and America/Chicago display timezone, fresh human login and user-run STS observation/result, all six allowed action categories, selected retention, independently approved wrapper, reconciled ownership, the resolved AWS CLI executable hash and the single new public packet root. The wrapper does not draft or write this gate. Unknown/missing fields and duplicate JSON keys fail closed. The future execution decision must include the offline AWS CLI capability check and the minimal environment's `AWS_MAX_ATTEMPTS=1` setting. No other approval meaning is inferred from booleans.

The window is at most one hour; the human login and STS must be inside it, with exact assumed-role identity. P3 absence must be no more than120 seconds old at initial apply. If the window, identity or P3 expires, stop and return to the coordinator; do not refresh/retry automatically. The wrapper never calls STS or login. A human-supplied STS JSON is not standalone MFA proof or proof of full OAuth refresh lifetime.

A clean source-controlled execution checkout and the human gate need not occupy the same checkout. Preserve the human-owned phase record in the human's evidence checkout; `--gate` names that public non-secret file and its externally verified SHA. This avoids trying to commit a gate that self-references its own commit. The approved execution commit must already contain the scripts/proposal and frozen sources; the wrapper checks HEAD, tracked script set/hashes, all209 source byte hashes and seven durable copies. No commit or dirty-tree exception is performed by this wrapper.

## Stage behavior

- `p3-check` checks the gate, clean execution checkout, pinned durable paths/hashes/modes, absence of all resource/recovery/backup/workspace-state/lock files, and a fresh exact human identity. It creates an exclusive operation directory. An offline `describe-budget --generate-cli-skeleton input` check must expose `ShowFilterExpression` before any live request. It then issues only exact-name DescribeBudget. Only CLI exit254 with the full anchored `NotFoundException` from `DescribeBudget`, no stdout and no mixed transport/auth indication, qualifies as absence. Exists, denial, expiry, malformed/blank output, wrong operation, network failures and unsupported capability all stop. The reviewed IAM permission basis is `budgets:ViewBudget` on the exact budget ARN; no nonexistent IAM action is invented and no policy is widened.
- `apply` requires the same gate/operation and fresh P3 receipt, rechecks the clean sources/context and no state, and reserves the fixed initial backup directory exclusively. It uses exactly the approved saved-plan argv with absolute `-state`, preserving locking and no `-state-out`, variable or planning flags. A saved-plan invocation executes without a second Terraform prompt; the human gate is therefore checked first. The apply allowance is separately capped at300 seconds rather than the60-second read limit, and before launch it reserves80 seconds of the human window (60 graceful-stop +5 forced-reap +15 local-preservation headroom). A shorter remaining window reduces the apply allowance; no apply starts without positive allowance beyond that reserve. After exit0, opaque no-follow state copying with fsync, stable identity and source/copy hashes completes immediately before checking window expiry or attempting readback. Local backup/preservation is unconditional even if the human window expires during completion; the successful apply/backup receipt then records no further live allowance and the mode stops. No AWS/readback continues after expiry. Receipt files contain metadata only.
- On any apply/backup error or interruption, further live calls stop. The bounded local preservation branch explicitly covers primary state, `.backup`, Terraform lock info and **config/errored.tfstate**, plus other scoped state/recovery artifacts. Copies use exclusive0600 names; files are not parsed, printed, edited, retried or deleted. Failed/incomplete preservation is an incident requiring human routing. A failed apply may have created resources even if no state was saved. The wrapper never imports, destroys, force-unlocks or rolls back. For Terraform apply, timeout or user interruption first sends one SIGINT only to the Terraform parent, leaving providers alive for Terraform's graceful stop/state persistence. It waits at most60 seconds without sending a second Terraform interrupt; repeated user interrupts do not restart that deadline. Only if Terraform is still running after that grace does it force-kill the isolated process group and allow up to5 seconds for reap. A private fixed-schema termination receipt records graceful versus forced/unknown exit. Forced termination can still leave cloud resources without complete state: preserve everything available and route an incident; never retry/adopt automatically. Read-only child timeouts keep their bounded group-cancellation path.
- `readback` requires the successful apply receipt and unchanged current/backup opaque hashes. It issues six fixed bounded requests in four operation families: budget, tags, notifications, subscribers for each of50/80/100. Paginated/truncated responses stop without another page or retry. It checks USD200 COST/CUSTOM, exact UTC dates, all11 CostTypes, no filters, exact five tags, exactly three ACTUAL/GREATER_THAN/PERCENTAGE notifications and one matching private EMAIL/zero SNS each. Output is a fixed allowlist of booleans/counts and stage metadata; no addresses, address hashes, spending totals, service error text or raw objects are emitted. Health is reported only as booleans; unknown/unhealthy status blocks verification. Delivery remains unverified until the human privately confirms what they actually observe.

Persistent stage-started journals prohibit replay after a failed or completed stage; gate/operation/plan/caller binding prevents cross-gate receipt reuse. A separate exclusive wrapper concurrency lock prevents overlapping stages and is removed only by its owning process. Terraform lock files are never removed by wrapper logic. Subsequent changes are outside this initial-create wrapper and need their own reviewed plan, gate and pre/post versioned backups.

P3 error-format compatibility is deliberately narrow: it accepts the legacy `An error occurred (NotFoundException) when calling the DescribeBudget operation: <body>` header and the observed CLI header `aws: [ERROR]: An error occurred (NotFoundException) when calling the DescribeBudget operation (reached max retries: 0): <body>`. The body must be nonblank and single-line. Exactly zero or one leading LF is accepted, matching the human-authorized layout check; two leading LFs, leading CRLF/CR, extra blank lines and arbitrary whitespace stripping are not accepted. The previously supported trailing layout remains zero or one LF/CRLF. ANSI, other prefix/annotation combinations, positive or ambiguous retry counts, wrong operations, non254 exits, stdout content and mixed auth/transport errors remain blocked. The zero annotation does not enable retries: `AWS_MAX_ATTEMPTS=1` remains unchanged. Synthetic fixture tests cover both formats and the rejection cases; no private response body is embedded in tests. This repair does not retroactively validate the stopped `billing-20261101-2030` attempt or authorize its replay. A reviewed new release and personally written gate/new operation are required before any fresh P3; the old gate and stage journals remain untouched.

## Final public packet scan

`post-freeze-scan` performs no cloud calls. After every public packet file is assembled and frozen, prepare a public manifest **outside** that packet, with exactly `root` and `files`. `root` is the human gate's `public_packet_root`, under `docs/agent-runs/phase-12/evidence/`; each entry has repository-relative `path`, `bytes` and `sha256`. The list must include every existing file in that packet, including its derived manifests. No arbitrary exclusions or symlink traversal are allowed. The exact full gate, script and frozen source bindings still apply.

Live stages require a wholly clean checkout. Only scan mode permits dirty/untracked files inside the gate's one new packet and the explicitly named external freeze manifest. Every script/source/other path must remain unchanged. This permits scanning newly assembled evidence before committing it; it does not waive the clean apply gate. If coordinator phase-record appends are also dirty in that checkout, scan blocks: use the separately approved clean source checkout/public packet workflow or sequence the scoped packet scan before unrelated phase-record appends. No automatic exception is granted. W3 remains an execution-gate requirement: after final assembly, include the final five public phase-record suffixes as byte-equal copies in the approved frozen packet, or obtain separate review of a broader scanner. A packet-only receipt does not cover later record appends or unrelated files. The coordinator must retain the exact suffix-copy comparison and final scan ordering; this repair does not broaden scanner code or claim that work already happened. W4 was supplied only as an unspecified information item and remains carried forward without an invented finding.

The authorized wrapper reads the approved private recipient only in memory for comparison; it never publishes/hashes it. It publishes a fixed-schema zero-match receipt on stdout **outside** the frozen packet, identifying the external manifest SHA and exact file count/time. The external manifest and this future receipt avoid circular hashes; every existing packet file was scanned. Do not add the receipt or any other new content to the packet and keep claiming the old scan: any addition/change requires a newly frozen manifest and rescan. A coordinator may link the external receipt after retaining it separately with a clearly declared scope. Source binding and completeness are checked again during scanning. This authoring task never reads the real recipient and does not claim an actual-recipient scan.

## W1/W2 repair scope and offline evidence

The repair changes only Terraform stopping/time budgets and unconditional local preservation plus their tests/documentation. A1 state-path and A2 errored-state coverage were accepted by the independent reviewer and remain closed; the isolated A1 test is rerun solely as regression after wrapper changes. New tests verify signal order and grace/forced paths with mocks and real local Python signal fixtures, repeated KeyboardInterrupt, separate timeouts/headroom, canonical verified backup after exit0 at the window edge, failed-window-edge partial preservation and no retry/live continuation. No real budget or durable private path is involved.

Pinned Terraform1.13.5 sources explain the graceful shutdown rationale: [commands.go](https://raw.githubusercontent.com/hashicorp/terraform/v1.13.5/commands.go) routes interrupts into ShutdownCh; [meta.go](https://raw.githubusercontent.com/hashicorp/terraform/v1.13.5/internal/command/meta.go) calls Stop on the first interrupt and Cancel on the next; [backend_apply.go](https://raw.githubusercontent.com/hashicorp/terraform/v1.13.5/internal/backend/local/backend_apply.go) persists returned state and provides errored.tfstate fallback. The wrapper sends only the first interrupt and preserves opaque state regardless of the operation result. This mitigates W1; it cannot guarantee cloud recovery after a genuinely unresponsive process or forced kill.

F1 layout recheck: the single human-authorized in-memory check on the previous parser returned accepted=false, one leading LF, one trailing LF and no CRLF. This narrow repair uses only synthetic fixtures reproducing those published layout facts; the saved private response is not re-evaluated with changed code, and no new real-input acceptance or budget-absence claim is made. F2 remains disclosed: test-only readiness markers wait for child handlers, while production timeout/shutdown behavior and assertions are unchanged.
