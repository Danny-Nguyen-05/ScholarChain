## Stage behavior

- `p3-check` checks the gate, clean execution checkout, pinned durable paths/hashes/modes, absence of all resource/recovery/backup/workspace-state/lock files, and a fresh exact human identity. It creates an exclusive operation directory. An offline `describe-budget --generate-cli-skeleton input` check must expose `ShowFilterExpression` before any live request. It then issues only exact-name DescribeBudget. Only CLI exit254 with the full anchored `NotFoundException` from `DescribeBudget`, no stdout and no mixed transport/auth indication, qualifies as absence. Exists, denial, expiry, malformed/blank output, wrong operation, network failures and unsupported capability all stop. The reviewed IAM permission basis is `budgets:ViewBudget` on the exact budget ARN; no nonexistent IAM action is invented and no policy is widened.
- `apply` requires the same gate/operation and fresh P3 receipt, rechecks the clean sources/context and no state, and reserves the fixed initial backup directory exclusively. It uses exactly the approved saved-plan argv with absolute `-state`, preserving locking and no `-state-out`, variable or planning flags. A saved-plan invocation executes without a second Terraform prompt; the human gate is therefore checked first. The apply allowance is separately capped at300 seconds rather than the60-second read limit, and before launch it reserves80 seconds of the human window (60 graceful-stop +5 forced-reap +15 local-preservation headroom). A shorter remaining window reduces the apply allowance; no apply starts without positive allowance beyond that reserve. After exit0, opaque no-follow state copying with fsync, stable identity and source/copy hashes completes immediately before checking window expiry or attempting readback. Local backup/preservation is unconditional even if the human window expires during completion; the successful apply/backup receipt then records no further live allowance and the mode stops. No AWS/readback continues after expiry. Receipt files contain metadata only.
- On any apply/backup error or interruption, further live calls stop. The bounded local preservation branch explicitly covers primary state, `.backup`, Terraform lock info and **config/errored.tfstate**, plus other scoped state/recovery artifacts. Copies use exclusive0600 names; files are not parsed, printed, edited, retried or deleted. Failed/incomplete preservation is an incident requiring human routing. A failed apply may have created resources even if no state was saved. The wrapper never imports, destroys, force-unlocks or rolls back. For Terraform apply, timeout or user interruption first sends one SIGINT only to the Terraform parent, leaving providers alive for Terraform's graceful stop/state persistence. It waits at most60 seconds without sending a second Terraform interrupt; repeated user interrupts do not restart that deadline. Only if Terraform is still running after that grace does it force-kill the isolated process group and allow up to5 seconds for reap. A private fixed-schema termination receipt records graceful versus forced/unknown exit. Forced termination can still leave cloud resources without complete state: preserve everything available and route an incident; never retry/adopt automatically. Read-only child timeouts keep their bounded group-cancellation path.
- `readback` requires the successful apply receipt and unchanged current/backup opaque hashes. It issues six fixed bounded requests in four operation families: budget, tags, notifications, subscribers for each of50/80/100. Paginated/truncated responses stop without another page or retry. It checks USD200 COST/CUSTOM, exact UTC dates, the strict cost-scope contract below, exact five tags, exactly three ACTUAL/GREATER_THAN/PERCENTAGE notifications and one matching private EMAIL/zero SNS each. Output is a fixed allowlist of booleans/counts and stage metadata; no addresses, address hashes, spending totals, service error text or raw objects are emitted. Health is reported only as booleans; unknown/unhealthy status blocks verification. Delivery remains unverified until the human privately confirms what they actually observe.

Persistent stage-started journals prohibit replay after a failed or completed stage; gate/operation/plan/caller binding prevents cross-gate receipt reuse. A separate exclusive wrapper concurrency lock prevents overlapping stages and is removed only by its owning process. Terraform lock files are never removed by wrapper logic. Subsequent changes are outside the initial-create modes and need their own reviewed plan, gate and pre/post versioned backups; the one reviewed change so far is the `modify` mode documented in the final section.

## Strict cost-scope representation contract — proposed repair

This offline repair requires independent acceptance before execution. [AWS Budget](https://docs.aws.amazon.com/aws-cost-management/latest/APIReference/API_budgets_Budget.html) marks `CostTypes` and `CostFilters` deprecated/optional and defines newer `Metrics` and `FilterExpression` fields. [AWS's compatibility explanation](https://aws.amazon.com/blogs/aws-cloud-financial-management/improving-accuracy-for-your-cloud-budgeting-with-new-features-in-aws-budgets/) describes responses containing only the newer representation. Missing legacy flags do not mean eleven false values.

The proposed fixed contract accepts exact legacy flags, or exactly `Metrics: ["UnblendedCost"]` with a sole `Not -> Dimensions` expression whose only keys are `Key: "RECORD_TYPE"` and `Values: ["Credit", "Refund"]`. The two distinct values may be reversed: [ExpressionDimensionValues](https://docs.aws.amazon.com/aws-cost-management/latest/APIReference/API_budgets_ExpressionDimensionValues.html) defines matching at least one value, and [Expression](https://docs.aws.amazon.com/aws-cost-management/latest/APIReference/API_budgets_Expression.html) defines `Not`. No general expression normalization is implemented. Explicit `MatchOptions`, extra operators/keys/values, other dimensions, arbitrary scope filters, malformed or unknown metrics, and absent modern metric/exclusion evidence are rejected. `CostFilters`, if present, must be an empty object. Legacy flags, if present alongside the new fields, must still match all eleven booleans exactly. A conflicting legacy field cannot be overridden by the newer representation. A metric supplied alongside legacy flags must also be exactly `UnblendedCost`.

Billing-view policy is **absence only**: any `BillingViewArn` key is rejected, including null, empty, malformed, custom, another account's view, or a primary-looking ARN. [AWS's billing-view guide](https://docs.aws.amazon.com/cost-management/latest/userguide/access-data-budgets.html) explains that a budget attached to a view tracks that view's scope. This verifier does not prove a supplied view's scope or infer safety from an ARN suffix, account substring or syntactic form. A returned primary-view ARN will therefore fail closed too. Neither authorized diagnostic projected this field, so its value in the saved response remains unknown. This offline repair does not inspect it or authorize another read.

The Budget object's field names are allowlisted to the fifteen keys documented by the [Budget API](https://docs.aws.amazon.com/aws-cost-management/latest/APIReference/API_budgets_Budget.html): `BudgetName`, `BudgetType`, `TimeUnit`, `AutoAdjustData`, `BillingViewArn`, `BudgetLimit`, `CalculatedSpend`, `CostFilters`, `CostTypes`, `FilterExpression`, `HealthStatus`, `LastUpdatedTime`, `Metrics`, `PlannedBudgetLimits`, and `TimePeriod`. Unknown keys fail closed. In addition to the billing-view rule, any presence of `AutoAdjustData` or `PlannedBudgetLimits` is rejected, even null or empty, because this contract requires a fixed USD200 limit. Known observational metadata such as `CalculatedSpend` and `LastUpdatedTime` can remain in the response, but its values are never published. The existing checks still govern required fields and health.

The all-eleven mapping below is an engineering inference from the [CostTypes meanings](https://docs.aws.amazon.com/aws-cost-management/latest/APIReference/API_budgets_CostTypes.html), the [separate aggregation and charge-type controls](https://docs.aws.amazon.com/cost-management/latest/userguide/bcm-lite-use-budget.html), and [AWS charge-type terminology](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/manage-cost-categories.html). It is not an AWS-published conversion table or a claim that these synthetic tests prove service accounting. Independent review must accept this precise inference before any post-create continuation; unresolved equivalence stays a blocker.

The [reviewed Terraform input](/Users/danny/Documents/UIC/CS441/ScholarChain/infra/terraform/billing-bootstrap/main.tf:28) specifies the eleven legacy cost flags and no scope filters. The separately human-authorized safe projections reported the corresponding saved AWS response as exactly `UnblendedCost` plus the sole Credit/Refund exclusion, with the legacy cost fields absent. ### What the code does

A Phase 12D create gate cannot authorize it, and a modify gate cannot drive the create modes. In order, it:

1. 3. Reserves a new operation directory (single use; no retry), then runs `terraform show -json` on the saved plan (offline). Create, delete, replace (either order), no-op, any other resource, any other attribute change, a `replace_paths` or `action_reason` marker, a wrong Terraform version or an errored plan all stop with a fixed code (`PLAN_CREATE`, `PLAN_DELETE`, `PLAN_REPLACE`, `PLAN_NOT_SINGLE_RESOURCE`, `PLAN_NOT_BILLING_RESOURCE`, `PLAN_NOT_IN_PLACE_UPDATE`, `PLAN_AMOUNT`, `PLAN_UNEXPECTED_ATTRIBUTE_CHANGE`, `PLAN_NOTIFICATIONS`, and so on). 4. Reads the live budget (six read-only requests). Live USD 200 / PERCENTAGE 50-80-100 (the Phase 12D shape, fully re-validated) continues. After exit 0 it requires Terraform's own `.backup` (if present) to equal the pre-apply state, copies the new state to `post-apply.billing.execution.tfstate` and requires it to differ from the old one.

### Rollback, realistically

There is no automatic rollback and no reverse mode. The saved Phase 12D create plan cannot be re-applied: it is a create plan against a state that now exists, and Terraform and the create modes refuse it. Returning to USD 200 would need new reviewed configuration, a new plan, a new gate and a new reviewed direction in this wrapper; that is deliberately not provided, because a USD 200 monitor would contradict the professor's cap. The practical recovery from a bad or partial modify is to fix forward to the USD 25 shape. The pre-apply and post-apply state copies and any preserved recovery files stay in `$BACKUPS/<operation>/`; the budget is an alerting monitor with no effect on resources or spend. The human (a) reads the live budget with the read-only verifier, (b) decides with the reviewer whether a fresh plan from the preserved state is an in-place update to the target, and (c) records a new gate. Restoring the pre-apply state file alone does not change AWS; use it only to rebuild a consistent plan input. The provider updates alerts by deleting and recreating them, so alerts may be missing, or sit at 50/80/100 percent of the new USD 25 amount, for a few seconds during the apply; confirm with the verifier afterwards.
