# Offline public publication helper

`publication_evidence.py` supports W3 evidence assembly and exact publication comparison. It never reads the real recipient, invokes the budget wrapper, calls AWS/Terraform, reads state/credentials or appends a phase record. This authoring task uses public synthetic temporary fixtures only. No production helper command was run, no actual public packet was frozen for execution, and no final publication or actual-recipient scan is claimed.

The accepted five original billing files remain byte-identical. These three new files must be independently reviewed and included in the later source commit and `wrapper_files` gate map. The budget wrapper enumerates **all eight files** under `scripts/billing/**`; a historical five-file map is no longer sufficient, although its accepted wrapper hash and semantics remain unchanged. Do not add generated bytecode/cache files to that directory. The helper does not alter the budget wrapper's fixed canonical location, clean-checkout rules, identity, window, hashes or permission gates.

Input staging is exactly one direct evidence child named `12d-publication-input-<identifier>`. Its `request.json` has exactly:

- `root`: one new direct evidence child `docs/agent-runs/phase-12/evidence/12d-publication-output-<identifier>`, also the later human gate's `public_packet_root`.

The helper's command options are a schema description, not a request to run them now. `assemble` takes `--repo` and `--request`. `verify-before` and `verify-after` take `--repo`, `--freeze`, `--freeze-sha256`, `--scan-receipt`, `--gate-sha256` and `--operation`. These are public repository-relative locations/hash metadata only. Unexpected modes/options print a fixed error code without echoing untrusted arguments. `--help` prints static usage. There is no publish/append/copy-to-destination, scanner, login, recovery or mutation mode for existing files.

## Assembly and freeze

`assemble` snapshots the five base records, reads exactly the selected staged public artifacts and suffixes, and checks all bytes again before its first output write. It exclusively creates the new output packet with0700directories/0600files and file/directory fsync. A preexisting packet or external freeze file blocks; it never overwrites or deletes partial output. Failed assembly is an incomplete preparation, not a successful freeze or permission to retry in place.

The packet contains the copied public `artifacts/`, all five `suffixes/`, and `publication-inventory.json`. That inventory binds the exact gate/operation/plan/caller; every artifact path/size/SHA; each destination's base length/SHA, suffix length/SHA and expected final base+suffix length/SHA. It includes all bytes, not merely an appended excerpt that might omit later content.

The external sibling `<packet>.freeze.json` has exactly the existing scanner's accepted `{root, files}` shape; every row has exactly `path`, `bytes`, `sha256`, and the list covers every packet file, including the publication inventory. This complete external manifest avoids recursive self-hashes. No internal manifest excludes arbitrary content. If an additional internal manifest/report is needed, it must be a selected artifact before assembly and is scanned like every other file. Any change/addition/removal invalidates the freeze/receipt; assemble a newly reviewed freeze rather than claiming the old receipt covers it.

## Scan receipt and publication comparisons

The actual-recipient scan remains exclusively the separately authorized budget wrapper's `post-freeze-scan`, under its human gate, identity/window and private-data policy. The helper does not invoke it or inspect its recipient. The genuine scan stdout must be captured privately outside the canonical checkout, retained under supervised provenance, and only its fixed public metadata result is supplied here.

The public scan receipt must be a direct evidence file named `12d-publication-scan-<identifier>.json`, outside the frozen packet. Its exact accepted keys match the existing scanner: gate SHA, operation, plan SHA, actor ARN, stage, observation time, public manifest SHA, file count, zero matches and the exact fixed exclusion description. Booleans masquerading as counts, extra payload fields, malformed time, changed operation/gate/plan/caller, wrong manifest/count or nonzero matches block. The expected gate hash and operation are also supplied independently to verification. A matching metadata receipt **does not authenticate the scanner or prove freshness**; both comparison modes explicitly return `scan_authenticity_verified=false`. Deployment supervision and independent review must establish genuine origin, approved window and immutable receipt provenance. The helper cannot validate private-state or live authorization.

`verify-before` rechecks the external manifest checksum, exact packet membership and every byte/hash, inventory completeness, all five current destination bases, exact suffixes and anticipated final bytes; it checks the supplied scan receipt binding, then checks content and destination hashes again. It returns fixed-schema booleans/counts and manifest SHA only. A successful result is a point-in-time comparison, not a lock over subsequent human writes. Do not concurrently edit or publish any destination.

Publication itself is a separately authorized coordinator/human operation: append only the exact scanned suffix bytes. This helper has no append mode. Immediately run `verify-after` against the actual canonical destinations. It verifies the entire destination file equals the expected base+suffix length/hash, its prefix retains the base hash, and its appended bytes equal the exact frozen suffix. Any extra word, missing suffix, changed prefix, artifact drift or later append fails; stop without reporting complete publication, and obtain new frozen coverage before publishing further changes. Do not attempt automatic rollback or overwrite. All final human-readable summaries intended for publication, including chat text, must come from scanned selected artifacts; fixed-schema receipt/comparison metadata are the only declared exclusions.

Keep the freeze manifest, genuine scan receipt and fixed-schema verification results external to the frozen packet; do not insert them into that packet and retain the old scan claim. Their allowed fields contain only fixed status/codes, checksums for public packet bindings, counts and booleans. They cannot carry arbitrary prose, recipient/address hashes or raw payloads. Helper output does not itself assert human gate authenticity or true publication. A partial/mismatching publication requires incident routing/new reviewed scope, not an unscanned corrective append.

## Compatible separate-workspace sequence

Staging inside the canonical checkout would violate the budget wrapper's scan-only dirty-path allowance. The intended later workflow is therefore:

1. Keep the canonical source-controlled checkout wholly clean for P3/apply/readback. The later gate must name the exact release including all eight script files and one new `12d-publication-output-...` packet root. An approved source-controlled preparation process creates a **separate public evidence workspace** with byte-equal copies of the canonical five base records, the selected public staging input and this helper; do not copy private input/raw logs/state.
2. Assemble in that separate public workspace. Transfer **only** the completed frozen output packet and external freeze manifest into the canonical evidence directory, without overwriting existing destinations. Verify transferred hashes against the freeze and canonical bases. No staging directory or scan receipt is introduced into the canonical checkout before scanning. The unchanged budget wrapper then sees only its gate-bound dirty packet and explicitly named external freeze manifest. This helper does not perform or authorize the transfer; its exact mechanism/actor belongs in the approved execution work order.
3. The human runs the separately approved wrapper scan in the persistent foreground Terminal. Capture stdout outside the canonical checkout; genuine provenance/time remains supervised evidence. After successful scanning, transfer only the fixed-schema public scan receipt to the allowed canonical evidence receipt location, then use `verify-before` against the canonical files and that receipt. The separate-workspace transfer test demonstrates matching bases pass and different canonical bases fail; workspace success alone is not canonical-publication proof.
4. Perform the approved exact-byte publication and `verify-after`. Receipt presence and later phase-record changes make the canonical checkout dirty outside the wrapper scan allowance. Therefore **do not invoke the wrapper again** from that now-dirty checkout or assume a later scan is permitted. If a rescan becomes necessary, stop for a separately reviewed handling procedure; no automatic receipt/staging deletion, stash, commit or waiver is supplied. No more live/readback stages are part of this publication phase.

The process is prepared but not yet executed, and W3 remains open until runtime final-publication evidence is observed. Source-control/clean canonical checkout, remaining human choices, R1 residual-risk acceptance, a personally written exact-checksum/identity/window gate, fresh P3 and all live billing/EMR conditions remain open. Existing accepted W1/W2/A1/A2 are not reopened. There is no spending, EMR or Phase12D completion claim.
