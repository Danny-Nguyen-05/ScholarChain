ID: M1
Severity: Medium
Location: budget_verification.py:172; VERIFICATION.md:34; test_budget_verification.py:55
Evidence and impact: The gap: the linkage reads the original gate from the hard-coded path PRIMARY/approval-20261102-attempt02.json. That name
appears in no public evidence, committed history or prior handoff; only the three new files contain it. The owner and coordinator reports do not
say where it came from.<br>Why it matters: this is an author-supplied default for an unknown private fact, which item 2 of the work order forbids.
If the name came from inspecting private files, that is an undisclosed boundary breach.<br>Consequence if wrong: the hash pin prevents
substitution, so the run fails closed, but only after the new operation journal is consumed, which costs a new gate, window and login.
Owner: infra-engineer; coordinator (provenance)
Acceptance: 1. State in the evidence how the path was chosen.<br>2. Unless a public, human-attested source establishes it, make it a human-pinned
value. For example, add a gate field for the filename, constrained to a direct child of the primary directory with a fixed safe pattern, or require
 confirmation in the separately authorized linkage preflight before the gate is written.<br>3. Add tests for a wrong path, a traversal or symlink
path, and a correct path.<br>4. Rerun all three suites.
