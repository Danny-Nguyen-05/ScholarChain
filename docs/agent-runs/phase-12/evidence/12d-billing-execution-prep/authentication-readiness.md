# Authentication remains a separate gate

Public documentation was checked on October 31, 2026; no account call, login or credential read ran. [AWS CLI browser-login documentation](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-sign-in.html) describes temporary credentials and a separate SignInLocalDevelopmentAccess prerequisite for the IAM identity. This authentication permission is not one of the five budget service permissions and is not installed by this draft. A later identity-establishment work order must review any login authorization separately, with exact account/region/client scope where supported. Do not infer that the caller-policy JSON alone is a complete operator setup.

[The CLI role documentation](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-role.html) describes MFA-aware role assumption. The public pages checked do not establish that this project’s browser-login workflow supplies the strict MultiFactorAuthPresent context required by the draft. Console/root MFA and temporary credentials alone do not prove it. Keep that compatibility unverified; do not create permanent keys or weaken trust to make the draft work. Actual credential/session setup, MFA verification and any alternate trust design require a separate bounded human-authorized work order. The chosen operator and its ARN remain unset.
