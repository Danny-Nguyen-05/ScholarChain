# ScholarChain threat model

Scope: the build-time agentic factory, the data pipeline (Hadoop, entity resolution, Spark), the AWS runtime (ALB, ECS services, Neptune, DynamoDB, S3, S3 Vectors) and the two external model providers (Anthropic API for synthesis, Voyage AI for embeddings). The architecture is in [docs/architecture.md](architecture.md); the HTTP surface is in [docs/api.md](api.md).

How to read it. Each threat lists the control as it exists in the code, the infrastructure files or the factory, the evidence that the control was exercised, and the residual risk. "Tested offline" means a committed test covers it; it does not mean the control was observed live. Nothing here was re-run in package 17A-1; test names come from the committed Phase 11 test report ([docs/agent-runs/phase-11/test-report.md](agent-runs/phase-11/test-report.md)) and the Phase 16 evaluation ([docs/report/evaluation.md](report/evaluation.md)). Where no evidence exists the text says "not verified".

## Summary

| # | Threat | Main controls | Residual risk (short) |
|---|---|---|---|
| 1 | Prompt injection in titles, abstracts, full text, profiles | retrieved text is untrusted data; forced typed tool output; deterministic claim verifier | live-model injection resistance not measured |
| 2 | Data poisoning, fabricated identifiers, edges, paths | exact-observation conflict rejection; ER hard conflicts; typed claims checked against stored evidence | a wrong upstream merge passes the graph audit |
| 3 | Secret exposure | Secrets Manager; hashed service tokens; read fences and redaction; no secrets in tracked files | one invalid key was pasted live; test fixtures look like secrets |
| 4 | Over-permissioned IAM | per-service roles, graph role read-only, deployer boundaries, roles removed after use | the shared course key has one authorization domain |
| 5 | Denial of service, queue flooding, unbounded graph queries, LLM cost | body, depth, scan, node, queue and rate bounds; deadlines; breakers; budgets and ledgers | a 5xx burst at 50 workers; no WAF; one NAT |
| 6 | Malformed and decompression-bomb inputs | per-record byte caps, entity-expansion cap, bounded blocks and teams, reject outputs | caps are tuned to the sample data |
| 7 | Cross-tenant or unauthorized evidence access | separate public and internal tokens; typed 401 | no per-user authorization exists |
| 8 | Destructive agent or operator commands | PreToolUse guard, deny list, one-writer map, scripts dry-run by default, human gates | the guard is conservative, not a sandbox; Codex and Cursor do not run it |
| 9 | Terraform state compromise | state and plans git-ignored, state hash binding, no secret values in Terraform | local plaintext state on one laptop |
| 10 | Provenance or audit tampering | content-bound evidence ids, immutable conditional writes, manifests with hashes, deterministic run ids | hashes prove consistency, not authenticity |

## 1. Prompt injection

Where retrieved or generated text reaches a model: source titles, abstracts and full text, institution and topic descriptions, generated profile text. In this system the model sees evidence text in the synthesis prompt; the planner sees the user question.

Controls:

- **Retrieved text is data.** Evidence is rendered into the prompt as JSON inside one untrusted block, so delimiter-looking text stays a string ([modules/rag/README.md](../modules/rag/README.md), Phase 9B and 9C). Test: `IndependentRuntime9BEvidenceSpec`, "retrieved delimiter injection stays JSON data inside one untrusted block".
- **Allowlisted plans.** The planner may only propose `QueryOperation` values; its JSON is validated against `prompts/schemas/query-plan-v1.json` with an explicit bounded JSON Schema subset, unsupported keywords fail closed, arbitrary Cypher, SQL or AWS requests are unsupported, and the model cannot remove a recognized constraint (Phase 9A section of the rag README). Graph queries are fixed parameterized templates; user ids, windows and cursors are parameters ([modules/storage/README.md](../modules/storage/README.md), `NeptuneGraphReader`).
- **Typed output.** Synthesis must return a forced tool call (`submit_answer`) that validates against `prompts/schemas/answer-synthesis-v2.json`; text blocks are rejected. The model proposes typed claims and claim ids only; factual prose and model uncertainty text are never trusted as facts.
- **Deterministic verification.** Every claim's type, subject, window and value is checked against stored evidence; rejected claims stay in the audit and are not rendered; vector evidence cannot authorize numeric or graph claims. Tests (all in the Phase 11 report): instruction-looking title, abstract and generated profile stay untrusted data and cannot change verified facts (`IndependentRuntime9CSynthesisSpec`); HTTP-level title, abstract and full-text injection reach real retrieval and the verifier and the replay keeps the audited abstention (`AdversarialRuntimeHttpSpec`); an injected instruction with a malicious count is rejected with source evidence retained (`AdversarialRuntimeWorkflowSpec`); a model fake citation or fake identity is rejected even when the JSON conforms to the schema.
- **Bounded model I/O.** Question, prompt, request, output and bundle byte limits; one malformed-output retry; planner and synthesis deadlines; a prompt estimated at 100,000 tokens or more is refused before any call.

Evidence from live runs: the Phase 16 independent scorer re-checked every claim the runtime marked verified against the Spark export: 36 of 36 in Q12 run 1 and 65 of 65 in run 2 were consistent, 0 contradictions ([answer-quality.md](../experiments/results/phase16/answers/answer-quality.md)). That measures answer correctness on a benign question set; it is not an injection test.

Residual risk. The rag README states that the offline tests establish contract behavior and "not evidence of general live-model injection resistance". No live injection test against `claude-haiku-5-5` exists in the evidence: not verified. Free-text contradictions outside the checked claims are not assessed ([evaluation](report/evaluation.md), group 4). Question text and evidence snippets leave AWS to the model provider ([docs/report/provider-fallback.md](report/provider-fallback.md), section 6).

## 2. Data poisoning and fabricated identifiers, edges and paths

Controls:

- **Conflicting observations are dropped, not merged.** Hadoop J04 compares complete observations of one source record and snapshot: identical copies keep one survivor, differing payloads drop both sides (`ConflictingObservation`); the counters `DUPLICATE` and `CONFLICT` expose both ([modules/hadoop/README.md](../modules/hadoop/README.md); lineage in [docs/data-lineage.md](data-lineage.md)). Test: "identical payloads survive once and conflicting payloads are not exported".
- **Identity is conservative.** Spark derives a researcher id from the exact DBLP name; a matching name is not identity evidence; ORCID conflicts inside one name group are warnings, never identity splits; accepted cross-name links stay unapplied; a work link group that violates a cannot-link or an authoritative identifier conflict is not merged ([modules/spark/README.md](../modules/spark/README.md), Job 1). The entity-resolution policy is offline, uncalibrated and has the LLM adjudicator disabled, so a model cannot invent a match ([config-sources.json](../experiments/inputs/15a/config-sources.json)).
- **Typed claims cannot name an invented entity.** A fabricated subject cannot borrow another researcher's stored metrics (`IndependentRuntime9CVerificationSpec`, "a fabricated subject cannot borrow another researcher's stored metrics"); a missing evidence id cannot authorize an otherwise correct count; a wrong stored count is rejected. Coauthor edges and path hops are checked against the support table (the Spark export validation rejects a support-row count different from `jointPublicationCount`).
- **Vector hygiene.** A same-dimension vector from a different model version is rejected; duplicate vector result keys reject the whole semantic result (`AdversarialRuntimeBoundarySpec`); a changed text hash is rejected before write.

Evidence: entity resolution on 194 held-out binary pairs accepted no pair labelled different (0 false positives; Wilson upper bound 3.1% on the false-merge rate) and withheld 15 of 72 true matches ([identity-metrics.md](../experiments/results/phase16/identity/identity-metrics.md)). Graph audit of the size S export: 0 dangling edges, 0 duplicate keys, 228,715 of 228,715 coauthor edges fully supported ([graph-correctness.md](../experiments/results/phase16/graph/graph-correctness.md)).

Residual risk. Both evaluations are internal. The graph audit "does not check facts against DBLP, OpenAlex, Crossref or ORCID, so a wrong merge made upstream by entity resolution would pass". The labels are AI-drafted and reviewed by one human. Common-name and cross-partition leakage risks remain ([evaluation](report/evaluation.md), groups 1 and 2). The size S slice is a convenience slice and source records are taken as published; a malicious source snapshot is not detected beyond schema, identifier and conflict checks.

## 3. Credential and secret exposure

Surfaces: logs, prompts, Terraform state, deployment-script output, Git history, chat transcripts.

Controls:

- **Runtime.** Provider keys and service tokens live in AWS Secrets Manager (four `scholarchain/course/*` secrets, created in Session 2: [a7-secrets.log](agent-runs/phase-15/evidence/session-2/a-setup/a7-secrets.log)); ECS execution roles can read only explicitly bound secret ARNs; Terraform contains no secret-version data source or secret-value resource ([infra/terraform/README.md](../infra/terraform/README.md), identity module). The services hold only the SHA-256 of each token and refuse to start without both hashes or if the two are equal (`ServiceConfig`). Request logs use an allowlist of correlation id, route template, status and duration; errors never carry provider messages, stack traces, bodies or queries. Test: synthetic credential, header and thrown-provider canaries stay absent from responses and logs (`AdversarialRuntimeHttpSpec`).
- **Factory.** The PreToolUse hook blocks Read, Write, Edit and shell access to `.env`, `secrets/`, `.aws/credentials`, `.ssh/`, `*.pem`, `*.key`, `id_rsa` and `id_ed25519` patterns ([.claude/hooks/guard-dangerous.sh](../.claude/hooks/guard-dangerous.sh), [.claude/settings.json](../.claude/settings.json)); private Terraform variable files (`*.tfvars` other than the committed non-secret ones), state and plans are git-ignored (`.gitignore`); the scripts mask private values as `<redacted>` and evidence copies pass a redaction filter that replaces account ids, home paths and e-mail addresses ([Session 2 INDEX](agent-runs/phase-15/evidence/session-2/INDEX.md), Redaction).
- **Operational.** Keys were entered by the human in the console; both Voyage keys were revoked on 2026-11-18 ([c5b-key-revocation.log](agent-runs/phase-15/evidence/session-2/section-c/c5b-key-revocation.log)); the four secrets were force-deleted ([c5-secrets-delete.log](agent-runs/phase-15/evidence/session-2/section-c/c5-secrets-delete.log)); the Q12 Anthropic key was revoked on 2026-11-21 ([q12-rerun-addendum.md](agent-runs/phase-15/q12-rerun-addendum.md)).

Residual risk.
- Session 2 ingest 1 failed because an invalid Voyage key had been pasted into the secret; the cause was found by a human key test ([incident](incidents/2026-11-18-vectors-ingest-1-voyage-401.md)).
- The repository contains synthetic secret-shaped strings in test fixtures, and the real AWS account id is present in the current tree and in history: 77 tracked files (73 under `docs/agent-runs/phase-12/`, 4 under `scripts/billing/`), 160 occurrences, introduced by 8 commits. The human's personal e-mail address is the author e-mail of 141 of 154 commits and appears in 30 record files under `docs/agent-runs/phase-07/` to `phase-13/` (inside a local folder path). Other people's addresses are copied unchanged from public sources (OpenAlex author records, a public signing-key file). Counts were observed by the coordinator on commit `b125d0f` and are not recomputed here; no value is printed in this file. The human decided on 2026-11-22 to keep all of it: no history rewrite and no new repository; new tracked files still add no account id or personal address ([human-decision-privacy.md](agent-runs/phase-17/human-decision-privacy.md)). These remain a disclosed residual risk of a public repository (spam, and a link between the address and the project).
- Root-console demo clips may show the human's e-mail ([decision log](agent-runs/phase-15/evidence/session-2/00-timeline/decision-log.md)); the clips are outside the repository.
- Terraform state can hold sensitive data in plaintext (threat 9).

## 4. Over-permissioned IAM

Controls:

- **Per-service roles.** Separate task and execution role per service; the graph task role has no write action, including no graph-bucket writes; ECS execution roles pull only their own repository, write only their own log streams and read only configured secret ARNs; the Neptune loader role trusts only RDS and reads only the graph bucket; EMR roles use S3, not DynamoDB ([infra/terraform/README.md](../infra/terraform/README.md), "Module boundaries and security controls", with a table of the individual wildcard exceptions and their reasons).
- **Deployer boundaries.** The deployer stack writes permission boundaries that cap what the application and loader roles can ever do; the default boundary contains no Bedrock access ([docs/report/provider-fallback.md](report/provider-fallback.md), section 4; [infra/terraform/deployer/README.md](../infra/terraform/deployer/README.md)). Four ECR repositories are immutable and scan on push.
- **Time-boxed human roles.** Operator roles (cleanup, loader, reader, pipeline) existed only for the session and were destroyed in cleanup block C4 (13 resources destroyed, [deployer-cleanup-apply-results.txt](agent-runs/phase-15/evidence/session-2/section-c/deployer-cleanup-apply-results.txt)); IAM windows were opened and closed by the human ([iam-window2-closed.txt](agent-runs/phase-15/evidence/session-2/section-c/iam-window2-closed.txt)); the deployer role and its seven policies were removed on 2026-11-19 (18 destroyed, [p39-deployer-removal.log](agent-runs/phase-15/evidence/session-2/p39/p39-deployer-removal.log)). Only `scholarchain-billing-deployer` was kept. The same pattern was repeated in Phase 18 on 2026-11-25: the deployer and operator roles were recreated in IAM window 1, the 13 operator-role resources were destroyed in C4 and the deployer role with its 18 resources was removed in P39 (IAM window 2, closed at 03:11:50Z on 2026-11-26); the final inventory again shows only `scholarchain-billing-deployer` among project roles ([Phase 18 test report](agent-runs/phase-18/test-report.md), Day 2; [p39-deployer-removal.log](agent-runs/phase-18/evidence/day2/p39/p39-deployer-removal.log)).
- **Not widened to fix a failure.** When a destroy failed on `ec2:DisassociateAddress` (403) the kit rule was not to widen IAM; a second pass was used instead ([cleanup-results.txt](agent-runs/phase-15/evidence/session-2/section-c/cleanup-results.txt)).
- **Authorization by plan.** Every apply is bound to an approved plan checksum, a pre-spend receipt and a state binding ([scripts/README.md](../scripts/README.md), Deploy stages).

Residual risk. The public API has one shared key and one authorization domain; a 403 policy is "reserved" ([modules/services/README.md](../modules/services/README.md)). Some wildcard exceptions are unavoidable (for example `ecr:GetAuthorizationToken`), listed in the Terraform README. The deployer's permission set was larger than the runtime roles for the duration of Sessions 1 and 2. The live effectiveness of the boundaries against a malicious principal was not tested.

## 5. Denial of service: flooding, unbounded graph queries and cost exhaustion

Controls (limits and defaults are from `ApiContracts.scala`, `GraphApi.scala`, `PublicSemanticRoute.scala`; see [docs/service-limits.md](service-limits.md) for the full list):

- **Request bounds.** Body at most 65,536 bytes (public semantic route 8,192), 5 s read timeout, JSON nesting at most 32, question at most 8,192 characters (public semantic route 1,000), filter counts and lengths bounded.
- **Concurrency and queues.** Four worker threads and a queue of 64; a full queue is a typed `429 THROTTLED` and a terminal, non-retryable failure for that key. Idempotency keys make a retry storm replay stored answers instead of new workflows. SQS has a dead-letter queue with `maxReceiveCount` 3 ([infra/terraform/README.md](../infra/terraform/README.md)).
- **Rate limit.** The public semantic route has a per-key token bucket, default 50 per second with burst 100, checked before validation; refusals are `429 RATE_LIMITED` with `Retry-After`.
- **Graph bounds.** Neighbor expansion depth at most 3, limit at most 200, scan cap 10,000 edges, node cap 2,000, per-request deadline 5 s, path depth at most 6 with a truncation flag so an empty result is never presented as "no path".
- **Downstream protection.** Per-dependency circuit breakers (3 failures, 30 s reset), a 5 s downstream timeout, at most 3 attempts, workflow retries capped at 2.
- **Cost.** A project ceiling of USD 25 with actual-cost alerts at USD 18, 20 and 22 ([incident record](incidents/2026-11-16-p0-budget-modify-backup-check.md), Summary); LLM answer buckets (14c 10, 15b 60, 16b 80, 17 10 = 160 answers) under a shared cap of USD 1.33 ([llm-allocation.json](../experiments/manifests/llm-allocation.json)); an embedding cap of USD 0.30 enforced by a token counter before each request ([modules/rag/README.md](../modules/rag/README.md)); an EMR ledger with a per-run cap and a live-run count ([run-experiment manifests](../experiments/manifests/15a-emr-size-100.json): `max_usd` 0.84, `max_runtime_minutes` 75, idle timeout at most 900 s); a teardown script that destroys the stack under a confirmed token.

Evidence: the aborted AWS load run `rb-20261118` held 0 errors through level 50, then a burst of 503 and 504 in `hold-50` (67 failed requests) ended it by the load generator's own 5xx guard ([evaluation](report/evaluation.md), group 5; [incident records](incidents/README.md)). Failure injection (stopping the query-api task) recovered in 113 s and 68 s in the two events that took effect.

Residual risk. The 5xx burst was not diagnosed to a root cause in the evidence. No WAF, no CDN and no per-IP limit exist; ALB ingress is limited to the operator's address in the deployed configuration, and public ingress defaults to empty. A single NAT gateway is a single-zone egress dependency. Throughput at two tasks was never measured. AWS budgets are alerts, not hard stops, and do not cover the Anthropic or Voyage bills.

## 6. Malformed and decompression-bomb inputs

Controls: `maxRecordBytes` 1,048,576 applied before a JSON line becomes a String (the excess is drained to the next newline); `maxXmlEntityExpansion` 1,048,576 with unsafe entities rejected (`UnsafeEntity`); a DBLP record reader that does not assume split alignment and an oversize-nested-XML drain that does not retain every tag name; a bounded launch sample; bounded blocks (32 members, 128 pairs) and teams (16 authors) with whole-group rejection and counters; a bounded lineage metadata budget with SHA-256 references. Tests: "an oversize JSON line is rejected before it is kept as a string", "valid 600k DBLP title expansion exports rejects with original source lineage", "oversize nested XML drains without retaining every tag name", and the adversarial blocking and graph-shape suites under `tests/` ([Phase 11 report](agent-runs/phase-11/test-report.md)). Observed on the size S run: `OVERSIZE_BLOCK` 517, `OVERSIZE_TEAM` 63, `REJECTED` 1,243 of 290,343 input records ([hadoop-prep-counters.txt](agent-runs/phase-15/evidence/session-2/emr/hadoop-prep-counters.txt)); these are observations of 2026-11-18, before the J08 change of 2026-11-26 that adds the counter `OVERSIZE_TEAM_PAIR_STEP` and one extra reject per oversize team in later runs ([data-lineage.md](data-lineage.md), Oversize teams).

Residual risk. The limits were chosen for the committed samples and one 10,577-record slice; behavior at full DBLP scale was never run. A full-corpus run would need new sizing (the Spark README notes executor-memory assumptions for larger runs).

## 7. Cross-tenant or unauthorized evidence access

Controls: two authentication domains with separate hashes; an external bearer cannot authorize an internal route and the internal token cannot authorize a query (`IndependentServices10ASpec`, "external bearer cannot authorize internal routes and internal token cannot authorize queries"); missing and wrong credentials are rejected before the workflow; evidence ids are looked up exactly and an unknown id is `404` (observed live in Session 2: [manual-401.log](agent-runs/phase-15/evidence/session-2/rb-runtime/manual-401.log), [p14-7-evidence-404.log](agent-runs/phase-15/evidence/session-2/rb-runtime/p14-7-evidence-404.log)). The ALB security group allowed only the human's address in Session 2 ([decision log](agent-runs/phase-15/evidence/session-2/00-timeline/decision-log.md), runtime plan entry).

Residual risk. There is no tenant concept: every holder of the one API key can read every evidence item and every query audit by id. Query and job ids are `qry-` and `job-` plus a SHA-256 of the idempotency key, so they cannot be guessed, but any holder of the shared key who obtains one can read that query's result, evidence and audit. The project is a single-user course system; multi-tenant isolation is not implemented.

## 8. Destructive agent and operator commands

Controls in the factory (the factory is documented in [docs/agents.md](agents.md), which this file references and does not restate):

- **One writer per artifact** and BLOCKED-ON routing for out-of-scope work; reviewer and test-engineer roles cannot edit production files; no agent approves its own work.
- **PreToolUse guard** ([.claude/hooks/guard-dangerous.sh](../.claude/hooks/guard-dangerous.sh)): blocks constitutional-file edits by any agent other than the factory, `terraform apply` and `destroy`, force pushes, `aws s3 rm`, destructive `aws` calls (`delete-`, `terminate-`, `cancel-`, `stop-`, `remove-` for S3, DynamoDB, Neptune, S3 Vectors, ECR, KMS, EMR, EC2), unreviewed EMR and autoscaling scale changes, and destructive SQL statements. The permission deny list in `.claude/settings.json` repeats the main ones. Observed during package 17A-1: a read-only shell command that named a constitutional path together with an interpreter was blocked by this hook, as the docs say the hook does for "harmless quoted probes".
- **Post-edit and stop hooks**: a Scala formatter, an agent-file validator, and a Stop hook that checks the test marker written only by a successful `sbt check` (`.claude/.last-test-run`).
- **Human gates.** Apply, deployment, scale changes, data destruction, security changes and rollback need a recorded human decision ([AGENTS.md](../AGENTS.md)). Cloud scripts are dry run by default; `deploy.sh`, `rollback.sh` and `cleanup.sh` refuse without an approval record, a fresh pre-spend receipt, a clean tree, a matching commit, the verified plan checksum and a live account check; cleanup destroys only with a token bound to the exact saved plan and refuses while deletion protection is on until a reviewed preparation step ran ([scripts/README.md](../scripts/README.md)).
- **Protected data stores.** Neptune, DynamoDB, ECR, S3 and S3 Vectors carry deletion protection or `force_destroy=false` until `cleanup_mode`; the runtime never receives a loader role.

Evidence: the cleanup rehearsal in Session 2 ran in two passes with a 201-delete listing refused by design until the human supplied the token ([cleanup-results.txt](agent-runs/phase-15/evidence/session-2/section-c/cleanup-results.txt)). The P0 budget incident shows the gates fail in a stopped, recoverable state ([incident record](incidents/2026-11-16-p0-budget-modify-backup-check.md)).

Residual risk. The guard is a conservative pattern matcher; indirect shell writes can bypass it, and a hook that cannot start may fail open ([docs/agents.md](agents.md), Escalation and gates). Its prerequisites are Bash, `jq` and Python 3. The hooks and `.claude/agents` apply when Claude Code is used; Codex and Cursor do not enforce them and rely on their own approvals plus the same human gates ([AGENTS.md](../AGENTS.md)). Two format items in `.claude/settings.json` and `.mcp.json` (hook command paths and a header value) were changed in Phase 17 package 17E: hook commands now use the `"$CLAUDE_PROJECT_DIR"/.claude/hooks/<name>.sh` form and the GitHub MCP header is a single `${GITHUB_MCP_AUTHORIZATION}` reference. The human ratified the change on 2026-11-22 ([ratification record](agent-runs/phase-17/ratification-17e.md), [work order](agent-runs/phase-17/work-order-3-hooks-mcp.md)), and the fresh-session hook probes ran the same day ([probe record](agent-runs/phase-17/hook-probes-17e.md)): four PASS (validator exit 0; `terraform destroy` blocked by the guard; a secret-path read denied by a permission rule; an orchestrator edit of `AGENTS.md` blocked by the guard) and one INCONCLUSIVE (the subagent edit of `.claude/settings.json` was rejected by Claude Code's settings validation before the guard, file unchanged).

## 9. Terraform state compromise

Controls: the course root has no remote backend; state, backup state, plans and private variable files are git-ignored (`*.tfstate`, `*.tfstate.*`, `*.plan`, `*.tfplan`, `*.tfvars`) and none is tracked in Git (`git ls-files` shows none under `infra/`); only checksums and summaries are committed; the deploy scripts bind every plan to the live state's lineage, serial and sha256 before apply, and re-check immediately before each apply; the state hash is recorded after each stage ([state-sha-after-stagea-base.log](agent-runs/phase-15/evidence/session-2/stage-a/state-sha-after-stagea-base.log)); no secret value is ever a Terraform resource; account id and account hash checks run against the live caller.

Residual risk. State is a plaintext local file on the operator's laptop and can contain sensitive attributes; whoever reads that file reads them. There is no state locking beyond the local file and no remote versioned backend. A second operator or machine was never exercised.

## 10. Provenance and audit-record tampering

Controls:

- **Content-bound evidence ids.** The evidence id of a runtime item hashes the complete item; a changed payload with an unchanged id fails validation ([modules/core/README.md](../modules/core/README.md)).
- **Immutable writes.** DynamoDB rows use conditional absent writes and reject changed content; S3 objects are written with `If-None-Match: *` and a stored `sha256`, read back with a bounded streamed check; the audit record is immutable and the answer is returned only after it is readable; keys include `/versions/`.
- **Hashed manifests and markers.** Each pipeline stage binds its inputs by run id, snapshot, retrieval date and checksum and writes a completion marker over its manifest; Spark run ids are a deterministic hash of the input manifests, config and code, so changed code gives a different id; table content hashes are order-independent Merkle hashes ([modules/spark/README.md](../modules/spark/README.md)).
- **Evidence archive.** Session 2 evidence was copied with sha256 per file and an index ([INDEX.md](agent-runs/phase-15/evidence/session-2/INDEX.md)); the Phase 16 raw results were frozen read-only with a `SHA256SUMS` file ([freeze-report.json](../experiments/results/phase16/q12-raw/freeze-report.json)).
- **Human decisions are not rewritten** by agents ([AGENTS.md](../AGENTS.md)).

Residual risk. The entity-resolution README says hashes "establish internal consistency, not external authenticity": anyone who can rewrite a file and its manifest together passes the check. Git history is mutable until the repository is frozen; the human decided not to rewrite history ([human-decision-privacy.md](agent-runs/phase-17/human-decision-privacy.md)). Some raw evidence stays outside the repository (git-ignored `target/`, laptop-only raw of the local load rehearsal); only hashes of it are committed.

## 11. Gaps this model does not close

- No penetration test and no dependency vulnerability scan is recorded in the evidence read for this file: not verified.
- Secret scanning: the Phase 16 freeze of the raw Q12 and 16B outputs ran a secret-pattern scan that found no matching file; the scan of the first freeze was not retained separately and every later scan is clean ([evaluation](evaluation.md), "Evaluation data and independence"; [freeze-report.json](../experiments/results/phase16/q12-raw/freeze-report.json); [raw-rb-20261118-freeze-note.json](../experiments/results/phase16/performance/raw-rb-20261118-freeze-note.json)). That scan covered those result files only, not the repository or its history.
- Infrastructure as code: no Terraform security scanner ran. Neither Trivy nor Checkov was installed at preflight; the manual review plus Terraform schema and feature checks was the approved fallback and "not an independent security approval or scanner result" ([infra/terraform/README.md](../infra/terraform/README.md), security review paragraph).
- Live-model injection resistance, ALB or WAF abuse behavior and the 5xx burst root cause are not measured.
- Commands named here were not replayed in 17A. The 17G clean-checkout replay (fresh clone of `main` at `d1d4fe7`, JDK 17, offline, 2026-11-22) ran `sbt -batch clean check`: 1,773 tests succeeded, 0 failed, 2 canceled. The full `scripts/check.sh` result on that clone, which includes the hooks and constitution gates, is in `docs/agent-runs/phase-17/17g-replay.md`. Controls were not exercised live.
